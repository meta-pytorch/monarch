9//! `Handle`: an observe-only handle to a background operation.
10//!
11//! A `Handle` wraps a `watch` channel that a producer fulfills exactly once with
12//! the operation's `PyResult<Py<PyAny>>`. You observe its eventual result:
13//! synchronously via `get()`, on an `asyncio` loop via `as_asyncio()`/`await`, or
14//! without blocking via `poll()`. The channel is multi-observer, so a resolved
15//! value stays observable by any number of later observers.
16//!
17//! The watch-channel mechanics live in [`HandleCore`].
18//!
19//! ## Handle invariants (HDL-*)
20//!
21//! Code that relies on or enforces an invariant is tagged `// HDL-N`, and each
22//! `#[cfg(test)]` test that attests one names it; read the matching entry below
23//! before changing a tagged site.
24//!
25//! Assumed of the shared core and producer (not enforced here):
26//! - **HDL-1 (single terminal completion).** The watch value goes `None` ->
27//!   `Some(_)` exactly once and is never reset (`Some` -> `Some`, `Some` ->
28//!   `None`). Relied on by [`HandleCore::wait_future`] (wait loop + `expect`),
29//!   [`HandleCore::poll`] (re-borrow across the GIL), and
30//!   [`PyHandle::wait_completion`] (discriminant check then GIL re-borrow). Held
31//!   by convention: every producer sends once, always `Some(_)` (including the
32//!   direct [`PyHandle::spawn`] producer). A send-once sender (a newtype
33//!   consuming the `watch::Sender`) could make it structural, hardening `poll`'s
34//!   re-borrow.
35//! - **HDL-2 (value encoding).** `None` is pending, `Some(Ok(_))` success,
36//!   `Some(Err(_))` a producer error.
37//!
38//! Guaranteed by this module:
39//! - **HDL-3 (non-consuming reads).** No read moves the value out: a
40//!   value-extracting read clones it (`clone_ref`), and a discriminant-only read
41//!   (`wait_completion`'s success fast path) borrows just the `Ok`/`Err` tag and
42//!   clones nothing. Either way any number of observers see the same result.
43//!   Enforced by construction: no read path moves the value.
44//! - **HDL-4 (drop does not cancel; drop never panics).** Dropping a `Handle`
45//!   never cancels its producer; a `Handle` observes, it does not own the
46//!   producer's lifecycle. Enforced by construction: a `Handle`'s core has
47//!   `abort_on_drop: None`, and `HandleCore::Drop` aborts only when
48//!   `abort_on_drop` is set. The abort is wrapped in `catch_unwind`, so an
49//!   `abort()` that panics at interpreter shutdown (the Tokio runtime already
50//!   gone) cannot escape `Drop` and abort the process.
51//! - **HDL-5 (GIL discipline).** No Python object is touched without the GIL,
52//!   and every acquisition goes through `monarch_with_gil{,_blocking}`. Enforced
53//!   by the crate's `#![deny(clippy::disallowed_methods)]` ban on raw
54//!   `Python::with_gil`/`attach` -- a hard compile error, not a `debug_assert`.
55//! - **HDL-6 (`WouldBlockRuntime` is `get()`'s alone *among the observers*).**
56//!   Of the `Handle` observers only `get()` raises it, and only in a Tokio
57//!   runtime context; `as_asyncio()`/`__await__` off a loop raise the native
58//!   `RuntimeError` instead. The exception type itself is not private to this
59//!   module: it marks synchronous APIs that refuse to enter or block on Tokio
60//!   from an existing Tokio runtime context. The Python layer also raises it for
61//!   fresh root-client bootstrap (`monarch._src.actor.actor_mesh`), the
62//!   blocking worker-loop wrappers (`monarch._src.actor.bootstrap`), and a
63//!   `returns_future` `.get()` that would block a running event loop
64//!   (`monarch._src.actor.returns_future`, RF-7).
65//! - **HDL-7 (`as_asyncio` publish).** The observer waits borrow-first (via
66//!   `wait_ready`, never `changed()`-first). The result is published on the
67//!   loop thread through `complete_asyncio_future`, by the wake reader
68//!   (HDL-17) or by the fallback's `call_soon_threadsafe` callback (HDL-21),
69//!   or, for a Handle already complete, by `as_asyncio` itself (HDL-22).
70//!   It sets a result only on a non-cancelled future, swallowing
71//!   `InvalidStateError`; any `StopIteration` (including subclasses) is wrapped
72//!   in `RuntimeError` first, since `set_exception` rejects `StopIteration`
73//!   (PEP 479). If the loop has closed, the fallback logs rather than panics
74//!   and the wake reader never runs. A wake-reader failure, including a
75//!   future whose `done()` raises, is reported through the future's loop
76//!   exception handler, as asyncio reports an exception from a callback.
77//! - **HDL-8 (`get()` loop-warning is call-pattern, not outcome).** `get()` on a
78//!   running asyncio loop warns regardless of whether the value is ready: it
79//!   flags the blocking-call-from-a-loop anti-pattern, not whether this call
80//!   happens to block. A ready value returns after warning; under a
81//!   warnings-as-errors filter the warning escalates to an error.
82//! - **HDL-9 (GIL/watch borrow discipline).** A `watch` borrow is never held
83//!   across a GIL acquisition or an `.await`. `poll` and `wait_completion`'s error
84//!   path drop their read guard before taking the GIL and re-borrow under it
85//!   (GIL-then-watch order, never the inverse against the producer's write-lock
86//!   `send`); the `wait_ready`/
87//!   `wait_future` loops drop the temporary `Ref` before each `.await`; and their
88//!   returned futures own a cloned receiver (`Send + 'static`, borrowing nothing
89//!   from `&self`), which is what lets `get()` `drop(slf)` + release the GIL
90//!   before blocking and lets `as_asyncio` `spawn` the observer. `as_asyncio`'s
91//!   fallback observer clones the value under the one GIL acquisition it makes
92//!   to schedule; its wake observer never reads the value (HDL-17). Enforced
93//!   partly by the compiler (`Send` bounds, the borrow checker on `drop(slf)`)
94//!   and partly by construction; exercised by the multi-observer/blocking
95//!   tests.
96//! - **HDL-10 (dropped producer surfaces, never hangs).** If every producer drops
97//!   its sender without sending, the wait loop's `changed().await?` yields a
98//!   `RecvError` converted to `RuntimeError("Handle producer ended without
99//!   publishing a result")` on the non-blocking (`poll`), sync
100//!   (`get`/`wait_future`), async (`as_asyncio`), and `wait_completion` paths,
101//!   so every observer receives the same producer-lifecycle failure rather than
102//!   waiting forever.
103//! - **HDL-11 (Python construction is paired).** Neither `Handle` nor
104//!   `_HandleCompleter` has `#[new]`. Internal Python may call the private
105//!   `_new_handle_pair()`, which atomically creates a pending `Handle` and its
106//!   sole producer. The factory initializes the completer with `Some(sender)`.
107//!   `set_exception()` rejects a non-`BaseException` before taking it; the first
108//!   `set_result()` or valid `set_exception()` takes it, producing the only
109//!   state transition to `None`, and any later completion attempt raises. No
110//!   sender clone escapes. Dropping the completer unresolved closes the channel
111//!   and surfaces through HDL-10. Python therefore cannot create a pending
112//!   `Handle` without its producer. Native producers remain the default; this
113//!   private pair is reserved for operations whose semantics and scheduling are
114//!   owned by Python.
115//! - **HDL-12 (`get()` timeout contract).** `get()` validates the timeout up
116//!   front (rejecting negative/NaN/non-finite as `ValueError` via
117//!   `try_from_secs_f64`, never panicking) and before the ready fast path, so an
118//!   invalid timeout raises deterministically even for a ready handle. A timeout
119//!   is non-cancelling: it raises `TimeoutError` while leaving the producer and
120//!   every observer untouched, so a later `poll()`/`get()`/`await` still observes
121//!   completion.
122//! - **HDL-13 (direct Rust producer).** A Rust caller can eagerly produce a
123//!   `Handle` from a `Send + 'static` future via [`PyHandle::spawn`], without a
124//!   `PyPythonTask`: it spawns one producer that converts the terminal value to
125//!   `Py<PyAny>` under `monarch_with_gil` and publishes it once through the shared
126//!   `send_result` helper (same one-shot core and unobserved-error policy as
127//!   pytokio's producers, HDL-1/HDL-2), with `abort_on_drop: None` (HDL-4).
128//!   [`PyHandle::wait_completion`] is the matching observer: it projects the
129//!   terminal value to `PyResult<()>`, touching neither the GIL nor the Python
130//!   value on the ready-success fast path (a discriminant-only read, HDL-3) and
131//!   cloning the `PyErr` under the HDL-9 borrow order only on the error path. Both
132//!   are `pub` Rust-only methods outside `#[pymethods]` (HDL-11).
133//! - **HDL-14 (Rust value observation is owned and non-consuming).**
134//!   [`PyHandle::wait_future`] returns a `Send + 'static` future over a cloned
135//!   watch receiver. The waiter borrows nothing from the `PyHandle`, survives
136//!   the wrapper being dropped, and leaves the terminal value available to
137//!   every other observer.
138//! - **HDL-15 (Rust ready construction starts no work).**
139//!   [`PyHandle::from_value`] constructs an already-complete, non-aborting core
140//!   without spawning a task. It is public to Rust callers but remains outside
141//!   `#[pymethods]`, preserving HDL-11's direct-construction restriction.
142//! - **HDL-16 (permanent Python identity).** `Handle` and `WouldBlockRuntime`
143//!   have the canonical module `monarch._rust_bindings.monarch_hyperactor.handle`.
144//!   The legacy `pytokio` module does not export `Handle`.
145//! - **HDL-17 (GIL-free completion wake).** For a Handle still pending when
146//!   `as_asyncio` is called, on a loop that accepts `add_reader`, the observer
147//!   task holds a `Notifier` (a token,
148//!   an mpsc sender and an `Arc<Waker>`) and the `wait_ready` future. It
149//!   publishes by pushing the token and writing the loop's pipe, never reading
150//!   the value and taking no GIL; the loop thread reads the value from the
151//!   `Handle` and sets it (see [`crate::handle_wake`]). Enforced by
152//!   construction: `Notifier` has no `Py<_>`, and the task body makes no
153//!   `monarch_with_gil` call.
154//! - **HDL-18 (notification ordering under supported pipe outcomes).** A
155//!   notifier pushes its token before writing the pipe, and the reader drains
156//!   the pipe before the queue, never returning between the two; both retry
157//!   `EINTR`. A write that succeeds or returns `EAGAIN` leaves a byte pending,
158//!   so a token pushed after a queue drain is delivered by a later wake.
159//!   `EPIPE` or a disconnected queue means the channel is gone and the token is
160//!   dropped. Any other errno is logged as a broken wake channel, not claimed
161//!   as delivered.
162//! - **HDL-19 (loop not retained).** The wake registry holds each loop as a
163//!   weak key and its channel through a weak reference; the loop's selector,
164//!   through the channel's reader callback, is the channel's only strong
165//!   owner. A channel holds no reference to its loop. It holds each pending
166//!   await's asyncio future strongly until delivery, cancellation or loop
167//!   close, because asyncio holds tasks weakly and that reference is the
168//!   waiting task's only owner outside the task's own cycle; `__traverse__`
169//!   exposes each entry's future and `Handle` object to the garbage collector.
170//!   Closing a loop therefore releases the channel-owned graph (the channel,
171//!   its read end, its entries, their futures and `Handle`s). The write end
172//!   stays open until every `Notifier` is dropped, so a loop closed while an
173//!   await waits on a `Handle` that never completes keeps that descriptor
174//!   (HDL-20). A loop dropped
175//!   without being closed while an await on a pending `Handle` is registered
176//!   is still freed by the collector. Not freed: a loop dropped without being
177//!   closed while an undelivered entry's `Handle` value references it, and any
178//!   independent cycle through a `Handle`, such as a value that references its
179//!   own `Handle`. Both run through `PyHandle`, which the garbage collector
180//!   does not traverse.
181//! - **HDL-20 (late wake is harmless).** A notify after its channel is gone is
182//!   dropped without error or panic: the send fails, or the write gets `EPIPE`.
183//!   This requires `SIGPIPE` to be ignored, as Rust's runtime and CPython set
184//!   it by default; in a process that restores `SIG_DFL`, a completion that
185//!   races loop teardown can kill the process. Every `Notifier` owns the write
186//!   end through its `Arc<Waker>` until its `Handle` completes, so no write
187//!   reaches a reused descriptor.
188//! - **HDL-21 (fallback).** For a Handle still pending, a loop whose
189//!   `add_reader` raises `NotImplementedError` or that cannot be weakly
190//!   referenced uses the `call_soon_threadsafe` path; HDL-7 applies there
191//!   unchanged.
192//! - **HDL-22 (ready shortcut).** `as_asyncio()` on a Handle that already holds
193//!   its outcome, a value, a stored exception or producer loss (HDL-10),
194//!   returns a loop future already completed with it through
195//!   `complete_asyncio_future`, with no observer task and no wake-channel
196//!   registration. Awaiting it returns without giving the loop a turn, as for
197//!   any finished asyncio future.

268/// Publish a completed background-task result to the shared watch channel.
269///
270/// Shared by `PyPythonTask` spawns, the direct [`PyHandle::spawn`] producer
271/// (HDL-13), and the private Python completion pair (HDL-11). If the receiver
272/// has already been dropped, `watch::Sender::send` returns the unsent value as
273/// `SendError`: no consumer can ever observe it. An unobserved error is logged
274/// with its producer-creation traceback when one was captured.
275pub(crate) fn send_result(
276    tx: watch::Sender<Option<PyResult<Py<PyAny>>>>,
277    result: PyResult<Py<PyAny>>,
278    traceback: Option<Py<PyAny>>,
279) {
280    if let Err(watch::error::SendError(Some(Err(pyerr)))) = tx.send(Some(result)) {
281        monarch_with_gil_blocking(GilSite::Traceback, |py| {
282            let tb = if let Some(tb) = traceback {
283                format_traceback(py, &tb).unwrap()
284            } else {
285                // No creation traceback was captured: either a capture-disabled
286                // PythonTask (the default when the env var is unset) or a direct
287                // Handle producer, which never captures one.
288                "creation traceback unavailable (PythonTask producers can set \
289                 `MONARCH_HYPERACTOR_ENABLE_UNAWAITED_PYTHON_TASK_TRACEBACK=1` to capture one)\n"
290                    .into()
291            };
292            tracing::error!(
293                "a background task errored but is not being awaited; this will not crash your \
294                program, but indicates that something went wrong.\n{}\nTraceback where the task \
295                was created (most recent call last):\n{}",
296                SerializablePyErr::from(py, &pyerr),
297                tb
298            );
299        });
300    }
301}

303/// The watch-channel mechanics behind a `Handle`.
304///
305/// The channel starts as `None` and is fulfilled once with `Some(Ok(obj))` or
306/// `Some(Err(pyerr))`. Cloning the receiver lets multiple observers see the same
307/// completion, so observation is non-consuming.
308pub(crate) struct HandleCore {
309    /// One-shot result channel. `None` until the producer completes.
310    rx: watch::Receiver<Option<PyResult<Py<PyAny>>>>,
311
312    /// When `Some`, dropping the core aborts the producing Tokio task through
313    /// this handle; `None` leaves the producer running (a detached producer, or
314    /// a core built from a ready value). The task's result is observed only via
315    /// `rx`, so only the `AbortHandle` is kept, never the `JoinHandle`.
316    abort_on_drop: Option<AbortHandle>,
317
318    /// Optional creation-site traceback, used when logging un-awaited errors.
319    traceback: Option<Py<PyAny>>,
320}
321
322impl HandleCore {
323    /// Construct a core from its parts.
324    pub(crate) fn new(
325        rx: watch::Receiver<Option<PyResult<Py<PyAny>>>>,
326        abort_on_drop: Option<AbortHandle>,
327        traceback: Option<Py<PyAny>>,
328    ) -> Self {
329        Self {
330            rx,
331            abort_on_drop,
332            traceback,
333        }
334    }
335
336    /// Construct a core that is already resolved with `value`.
337    ///
338    /// There is no producer task, so the core never aborts on drop and carries
339    /// no traceback.
340    pub(crate) fn from_value(value: Py<PyAny>) -> PyResult<Self> {
341        let (tx, rx) = watch::channel(None);
342        tx.send(Some(Ok(value))).map_err(to_py_error)?;
343        Ok(Self {
344            rx,
345            abort_on_drop: None,
346            traceback: None,
347        })
348    }
349
350    /// Non-blocking, non-consuming check for completion.
351    ///
352    /// Returns `Ok(None)` while pending, `Ok(Some(obj))` on success, or
353    /// `Err(pyerr)` if the producer completed with an exception or disappeared
354    /// before completion.
355    pub(crate) fn poll(&self) -> PyResult<Option<Py<PyAny>>> {
356        // HDL-9: release the watch read guard before taking the GIL; holding it
357        // across the GIL acquisition would invert lock order against the
358        // producer's write-lock send. Re-borrowing under the GIL is safe by HDL-1
359        // (one-shot: once `Some`, never reset or replaced).
360        if self.rx.borrow().is_none() {
361            #[cfg(test)]
362            if let Some(between) = POLL_BETWEEN_CHECKS.with(|hook| hook.borrow_mut().take()) {
363                between();
364            }
365            // HDL-10: a closed channel with no value is terminal producer loss,
366            // not a still-pending Handle. `has_changed` also reports a channel
367            // closed just after a send, so read the value again after it.
368            let closed = self.rx.has_changed().err();
369            if self.rx.borrow().is_none() {
370                return match closed {
371                    Some(err) => Err(handle_producer_ended_error(err)),
372                    None => Ok(None),
373                };
374            }
375        }
376        monarch_with_gil_blocking(GilSite::Convert, |py| {
377            match self
378                .rx
379                .borrow()
380                .as_ref()
381                .expect("HDL-1: value is Some after the is_none check")
382            {
383                Ok(v) => Ok(Some(v.clone_ref(py))),
384                Err(err) => Err(err.clone_ref(py)),
385            }
386        })
387    }
388
389    /// Return a future that observes this core's completion.
390    ///
391    /// The receiver is cloned, so this is non-consuming: any number of waiters
392    /// can observe the same final value. The current value is checked before
393    /// awaiting `changed()`, so a core that already holds its value resolves
394    /// immediately.
395    pub(crate) fn wait_future(
396        &self,
397    ) -> impl Future<Output = PyResult<Py<PyAny>>> + Send + 'static + use<> {
398        // Reuse wait_ready's HDL-1 wait loop (single source of truth), then clone
399        // the value out under the GIL.
400        let ready = self.wait_ready();
401        async move {
402            let rx = ready.await?;
403            monarch_with_gil(GilSite::Convert, |py| {
404                match rx
405                    .borrow()
406                    .as_ref()
407                    .expect("HDL-1: value is Some after wait_ready")
408                {
409                    Ok(v) => Ok(v.clone_ref(py)),
410                    Err(err) => Err(err.clone_ref(py)),
411                }
412            })
413            .await
414        }
415    }
416
417    /// Await this core's completion without touching the GIL.
418    ///
419    /// Yields the cloned receiver positioned at the completed value, or a
420    /// `RuntimeError` if every producer dropped its sender without sending. Unlike
421    /// `wait_future`, which clones the value out under its own GIL acquisition,
422    /// the caller decides where the value is read: `as_asyncio`'s fallback
423    /// clones it under the GIL it takes to schedule, and its wake path reads it
424    /// on the loop thread instead (HDL-17).
425    pub(crate) fn wait_ready(
426        &self,
427    ) -> impl Future<Output = PyResult<watch::Receiver<Option<PyResult<Py<PyAny>>>>>>
428    + Send
429    + 'static
430    + use<> {
431        // HDL-9: the returned future owns a cloned receiver (Send + 'static,
432        // borrowing nothing from &self), so a caller can drop its PyRef / release
433        // the GIL before awaiting and can spawn this future.
434        let mut rx = self.rx.clone();
435        async move {
436            // HDL-1: loop until the value is actually `Some` (one-shot). HDL-9:
437            // the temporary borrow is dropped before each `.await`, never held
438            // across it. HDL-10: a dropped producer makes `changed()` yield a
439            // RecvError, which becomes the producer-lifecycle error rather than
440            // leaking the watch-channel implementation or hanging.
441            while rx.borrow().is_none() {
442                rx.changed().await.map_err(handle_producer_ended_error)?;
443            }
444            Ok(rx)
445        }
446    }
447
448    /// Clone the creation-site traceback under the GIL.
449    pub(crate) fn traceback_clone(&self) -> Option<Py<PyAny>> {
450        self.traceback
451            .as_ref()
452            .map(|t| monarch_with_gil_blocking(GilSite::Traceback, |py| t.clone_ref(py)))
453    }
454}

456/// Abort the producing Tokio task on drop when `abort_on_drop` is set.
457///
458/// This stops abandoned background work when no observers remain, guarded against
459/// panics during interpreter shutdown when the Tokio runtime may already be gone.
460/// A `Handle`'s core has `abort_on_drop: None` (HDL-4), so this aborts only for
461/// pytokio's `spawn_abortable`, never for a `Handle`.
462impl Drop for HandleCore {
463    fn drop(&mut self) {
464        if let Some(abort_handle) = self.abort_on_drop.as_ref() {
465            // HDL-4: catch_unwind so an abort() that panics at interpreter
466            // shutdown (the runtime already gone) cannot escape Drop and abort
467            // the process.
468            let _ = std::panic::catch_unwind(std::panic::AssertUnwindSafe(|| {
469                abort_handle.abort();
470            }));
471        }
472    }
473}

475/// Private one-shot producer paired with a Python-visible `Handle`.
476///
477/// The class has no Python constructor. `_new_handle_pair()` creates it with
478/// the only sender for its Handle; completion consumes that sender before
479/// publishing, and dropping it unresolved closes the channel (HDL-10/HDL-11).
480#[pyclass(
481    name = "_HandleCompleter",
482    module = "monarch._rust_bindings.monarch_hyperactor.handle"
483)]
484pub(crate) struct PyHandleCompleter {
485    // `Some` from `_new_handle_pair()` until the first valid completion;
486    // `None` thereafter.
487    tx: Option<watch::Sender<Option<PyResult<Py<PyAny>>>>>,
488}
489
490impl PyHandleCompleter {
491    /// Publish the terminal result exactly once.
492    fn complete(&mut self, result: PyResult<Py<PyAny>>) -> PyResult<()> {
493        let tx = self
494            .tx
495            .take()
496            .ok_or_else(|| PyRuntimeError::new_err("Handle has already been completed"))?;
497        send_result(tx, result, None);
498        Ok(())
499    }
500}

565    /// Native producers build the core and hand back an observe-only `Handle`
566    /// through this; `PyHandle`'s field is private to this module.
567    pub(crate) fn from_core(core: HandleCore) -> Self {
568        Self { core }

571    /// Construct an already-complete `Handle` from `value` without spawning a
572    /// producer task (HDL-15).
573    ///
574    /// Rust-only and outside `#[pymethods]`, so making this method public does
575    /// not make `Handle` directly constructible from Python (HDL-11).
576    pub fn from_value(value: Py<PyAny>) -> PyResult<Self> {
577        Ok(Self {
578            core: HandleCore::from_value(value)?,
579        })

582    /// Return an owned, non-consuming Rust observer for this Handle's value
583    /// (HDL-14).
584    ///
585    /// The returned future owns a cloned watch receiver, so it borrows nothing
586    /// from `self`, survives the `PyHandle` being dropped, and can coexist with
587    /// any number of other observers.
588    pub fn wait_future(
589        &self,
590    ) -> impl Future<Output = PyResult<Py<PyAny>>> + Send + 'static + use<> {
591        self.core.wait_future()
592    }

594    /// Non-blocking, non-consuming read of this Handle's outcome, for the
595    /// loop-thread wake reader (HDL-17). Rust-only and outside `#[pymethods]`
596    /// (HDL-11).
597    pub(crate) fn poll_ready(&self) -> PyResult<Option<Py<PyAny>>> {
598        self.core.poll()
599    }

601    /// Eagerly drive a Rust future to completion and return an observe-only
602    /// `Handle` over its result (HDL-13).
603    ///
604    /// The producer spawns immediately on the shared Tokio runtime; the returned
605    /// `Handle` observes already-running work rather than starting it lazily on
606    /// first observation. On completion the terminal `PyResult<T>` is converted
607    /// to `Py<PyAny>` under `monarch_with_gil` and published exactly once through
608    /// the shared `send_result` helper (HDL-1/HDL-2). The core carries
609    /// `abort_on_drop: None`, so dropping the `Handle` never cancels the producer
610    /// (HDL-4). Rust-only and outside `#[pymethods]`, so Python still cannot mint
611    /// a core (HDL-11).
612    pub fn spawn<F, T>(fut: F) -> Self
613    where
614        F: Future<Output = PyResult<T>> + Send + 'static,
615        T: for<'py> IntoPyObject<'py> + Send,
616    {
617        let (tx, rx) = watch::channel(None);
618        get_tokio_runtime().spawn(async move {
619            // Convert the terminal value to a Python object under the GIL, the
620            // same shape as `PyPythonTask` producers.
621            let result = async {
622                let value = fut.await?;
623                monarch_with_gil(GilSite::Convert, |py| value.into_py_any(py)).await
624            }
625            .await;
626            // HDL-1/HDL-2/HDL-13: publish exactly once via the shared helper; a
627            // direct Rust producer carries no creation traceback.
628            send_result(tx, result, None);
629        });
630        // HDL-4: a `Handle`'s core never aborts its producer on drop.
631        PyHandle::from_core(HandleCore::new(rx, None, None))
632    }
633
634    /// Observe whether this handle completed successfully, projecting the terminal
635    /// value to `PyResult<()>` (HDL-13).
636    ///
637    /// Returns an owned `Send + 'static` future over a cloned receiver (HDL-9),
638    /// so multiple Rust callers can observe the same terminal state and dropping
639    /// the `Handle` after taking an observer does not abort the producer (HDL-4).
640    /// The ready-success fast path touches neither the GIL nor the Python value
641    /// (a discriminant-only read, HDL-3); only the error path clones the stored
642    /// `PyErr`. This is the readiness surface for callers that need only the
643    /// success/error discriminant, not the value.
644    pub fn wait_completion(&self) -> impl Future<Output = PyResult<()>> + Send + 'static + use<> {
645        let ready = self.core.wait_ready();
646        async move {
647            let rx = ready.await?;
648            // Read only the success/error discriminant under a watch borrow that
649            // holds no GIL, then drop it. HDL-1: the value is `Some` and, once
650            // set, never changes.
651            let is_err = rx
652                .borrow()
653                .as_ref()
654                .expect("HDL-1: value is Some after wait_ready")
655                .is_err();
656            if !is_err {
657                return Ok(());
658            }
659            // Error path only. HDL-9: acquire the GIL first, then re-borrow the
660            // watch value (GIL-then-watch order, never the inverse); the
661            // discriminant borrow above is already dropped, so the two are never
662            // held together, and HDL-1 guarantees the same terminal `Err` is still
663            // there to clone.
664            monarch_with_gil(GilSite::Convert, move |py| -> PyResult<()> {
665                Err(rx
666                    .borrow()
667                    .as_ref()
668                    .expect("HDL-1: value is Some after wait_ready")
669                    .as_ref()
670                    .expect_err("HDL-1: error branch, discriminant already checked")
671                    .clone_ref(py))
672            })
673            .await
674        }
675    }

678/// Run `operation` only after `ready` resolves `Ok`, returning the readiness
679/// error unchanged if it does not.
680///
681/// Generic over the result and error so the short-circuit law is unit-testable
682/// without pyo3; the RDMA bindings instantiate `E = PyErr` and this helper never
683/// inspects or remaps it. `operation` is a closure, not an already-started
684/// future, so no effect begins before readiness. The typical `ready` input is
685/// [`PyHandle::wait_completion`].

688    RF: Future<Output = Result<(), E>>,
689    Op: FnOnce() -> OF,
690    OF: Future<Output = Result<T, E>>,
691{
692    ready.await?;
693    operation().await
694}

772impl PyHandle {
773    /// Block the calling thread until the handle resolves and return its value.
774    ///
775    /// Behavior is keyed to the calling context, not to whether the value
776    /// happens to be ready:
777    ///   - Tokio runtime context: raise `WouldBlockRuntime` unconditionally
778    ///     (blocking there would panic the runtime); use `poll()` or
779    ///     `as_asyncio()` instead.
780    ///   - running `asyncio` loop: warns (get() is a blocking call from a loop),
781    ///     then a ready value returns via the `poll()` fast path and a pending
782    ///     one blocks. Under a warnings-as-errors filter the warning is an error.
783    ///   - sync thread: a ready value fast-paths, a pending one blocks
784    ///     (Ctrl-C-safe on main).
785    ///
786    /// `get()` is non-cancelling. On timeout it raises `TimeoutError`, leaving
787    /// the producer and every observer untouched, so a later
788    /// `poll()`/`get()`/`await` still observes completion.
789    #[pyo3(signature = (timeout = None))]
790    fn get(slf: PyRef<'_, Self>, py: Python<'_>, timeout: Option<f64>) -> PyResult<Py<PyAny>> {
791        // HDL-6: among the observers, get() is the sole WouldBlockRuntime
792        // raiser. It is the blocking API, and in a Tokio runtime context
793        // blocking would panic the runtime, so refuse unconditionally -- even
794        // a ready value -- keying the outcome to context, not producer timing.
795        if is_in_tokio_runtime() {
796            return Err(WouldBlockRuntime::new_err(
797                "get() cannot be called from a Tokio runtime context; use poll() or as_asyncio()",
798            ));
799        }
800
801        // HDL-12: validate the timeout up front, so an invalid value raises
802        // ValueError deterministically rather than only when the handle happens
803        // to be pending. Reject negative/NaN/non-finite rather than panicking in
804        // Duration::from_secs_f64.
805        let duration = timeout
806            .map(|seconds| {
807                std::time::Duration::try_from_secs_f64(seconds)
808                    .map_err(|e| PyValueError::new_err(format!("invalid timeout {seconds}: {e}")))
809            })
810            .transpose()?;
811
812        // Warn regardless of readiness: get() is a blocking call, and calling it
813        // from a running asyncio loop is the anti-pattern being flagged whether or
814        // not the value happens to be ready this time (a later call may block and
815        // freeze the loop). Under a warnings-as-errors filter this escalates to an
816        // error -- the caller's chosen strictness for the anti-pattern.
817        if pyo3_async_runtimes::get_running_loop(py).is_ok() {
818            let category = py.get_type::<PyUserWarning>();
819            PyErr::warn(
820                py,
821                &category,
822                c"Blocking get() was called from a running asyncio event loop. It is a synchronous, blocking call that can freeze the loop and deadlock; use as_asyncio() (or await) instead.",
823                1,
824            )?;
825        }
826
827        // A ready value returns without blocking, in any non-Tokio context.
828        if let Some(value) = slf.core.poll()? {
829            return Ok(value);
830        }
831
832        let wait = slf.core.wait_future();
833        // HDL-9: drop the PyRef before releasing the GIL in `signal_safe_block_on`
834        // (which blocks with the GIL released), so a concurrent mutable borrow of
835        // this handle does not throw during the blocking window.
836        drop(slf);
837
838        // HDL-12: the timeout drops only the local `wait` future, leaving the
839        // producer and the watch channel untouched, so a timed-out get() stays
840        // observable (non-cancelling).
841        match duration {
842            Some(duration) => signal_safe_block_on(py, async move {
843                tokio::time::timeout(duration, wait)
844                    .await
845                    .map_err(|_| PyTimeoutError::new_err(()))?
846            })?,
847            None => signal_safe_block_on(py, wait)?,
848        }
849    }
850
851    /// Non-blocking, non-consuming check for completion.
852    ///
853    /// Returns `None` while pending, the value on success, or raises the stored
854    /// exception. If the producer disappears before completion, raises the
855    /// producer-lifecycle `RuntimeError`. A ready value stays observable by
856    /// later observers.
857    fn poll(&self) -> PyResult<Option<Py<PyAny>>> {
858        self.core.poll()
859    }
860
861    /// Return a standard `asyncio.Future` that resolves when the handle does.
862    ///
863    /// Requires a running loop; off a loop this raises the native `RuntimeError`
864    /// from `asyncio.get_running_loop()`. A Tokio observer of the watch channel
865    /// waits for completion; it never drives a Python coroutine. It then wakes
866    /// the loop through the loop's [`LoopWake`] channel without the GIL, and the
867    /// loop thread reads the value and sets the result (HDL-17). It instead
868    /// takes the GIL and publishes via `loop.call_soon_threadsafe(...)` when the
869    /// loop's `add_reader` raises `NotImplementedError`, or when the loop cannot
870    /// be weakly referenced (HDL-21). Any other failure to install the channel
871    /// or register the future is raised.
872    ///
873    /// A Handle that already holds its outcome returns a future already
874    /// completed with it, and starts no observer (HDL-22). For a pending
875    /// Handle, the observer borrows the current watch value first, so a core
876    /// that completes before the observer starts resolves rather than hangs.
877    /// The result is set on the loop thread. A cancel can race that: a
878    /// cancelled future is left alone and the handle continues. If the loop has
879    /// closed by then, the result is never set, and nothing panics.
880    ///
881    /// Each call on a pending Handle spawns its own observer; cancelling the
882    /// returned future does not stop the observer, which exits when the handle
883    /// resolves.
884    fn as_asyncio<'py>(slf: PyRef<'_, Self>, py: Python<'py>) -> PyResult<Bound<'py, PyAny>> {
885        // HDL-6: off a loop this yields the native RuntimeError, not WouldBlockRuntime.
886        let event_loop = pyo3_async_runtimes::get_running_loop(py)?;
887        let fut = event_loop.call_method0("create_future")?;
888
889        // HDL-22: `poll()` registers no waiter. A value that arrives after it
890        // is found by the observer's borrow-first wait below.
891        match slf.core.poll() {
892            Ok(Some(value)) => {
893                complete_asyncio_future(&fut, false, value)?;
894                return Ok(fut);
895            }
896            Err(err) => {
897                complete_asyncio_future(&fut, true, err.into_value(py).into_any())?;
898                return Ok(fut);
899            }
900            Ok(None) => {}
901        }
902        let wait = slf.core.wait_ready();
903
904        if let Some(channel) = LoopWake::for_loop(py, &event_loop)? {
905            let notifier = LoopWake::register(&channel, &fut, slf.into())?;
906            get_tokio_runtime().spawn(async move {
907                // HDL-17: no GIL on this task. Dropping the receiver before the
908                // pipe write means a readable pipe proves the task got past it.
909                drop(wait.await);
910                notifier.notify();
911            });
912            return Ok(fut);
913        }
914
915        // HDL-21: the fallback, for a loop without a channel.
916        let loop_handle = event_loop.clone().unbind();
917        let fut_handle = fut.clone().unbind();
918
919        get_tokio_runtime().spawn(async move {
920            let recv = wait.await;
921            let scheduled = monarch_with_gil(GilSite::Convert, move |py| {
922                // HDL-9: one GIL section that borrows the watch value under the
923                // already-held GIL (GIL-then-watch order), clones it out (or turns
924                // a dropped-producer RecvError into a PyErr), and schedules it --
925                // completion touches the GIL exactly once.
926                let result: PyResult<Py<PyAny>> = match recv {
927                    Ok(rx) => match rx
928                        .borrow()
929                        .as_ref()
930                        .expect("HDL-1: value is Some after wait_ready")
931                    {
932                        Ok(v) => Ok(v.clone_ref(py)),
933                        Err(err) => Err(err.clone_ref(py)),
934                    },
935                    // HDL-10: a dropped producer surfaces as a set_exception.
936                    Err(e) => Err(e),
937                };
938                schedule_completion(py, loop_handle.bind(py), fut_handle.bind(py), result)
939            })
940            .await;
941            if let Err(err) = scheduled {
942                tracing::warn!("as_asyncio: failed to schedule completion on the loop: {err}");
943            }
944        });
945
946        Ok(fut)
947    }

949    /// Implement Python's `await` protocol by delegating to `as_asyncio()`.
950    fn __await__<'py>(slf: PyRef<'_, Self>, py: Python<'py>) -> PyResult<Bound<'py, PyAny>> {
951        Self::as_asyncio(slf, py)?.call_method0("__await__")
952    }

957        cls.clone().unbind().into()
958    }

961/// The cached `complete_asyncio_future` callable.
962///
963/// The function is stateless, so it is wrapped once and reused for every
964/// completion rather than rebuilt (and leaked) on each `call_soon_threadsafe`.
965fn cached_completer(py: Python<'_>) -> PyResult<Bound<'_, PyCFunction>> {
966    static COMPLETER: PyOnceLock<Py<PyCFunction>> = PyOnceLock::new();
967    COMPLETER
968        .get_or_try_init(py, || {
969            Ok(wrap_pyfunction!(complete_asyncio_future, py)?.unbind())
970        })
971        .map(|f| f.bind(py).clone())

974/// Schedule the handle's completion onto `event_loop` from the Tokio observer.
975///
976/// Runs under the GIL. The caller has already cloned the success value; an error
977/// is turned into its Python exception object here, so no Rust `PyErr` crosses
978/// into the loop callback. `complete_asyncio_future` is then scheduled via
979/// `call_soon_threadsafe`, whose error (e.g. a closed loop) is returned so the
980/// caller can log rather than panic.
981fn schedule_completion(
982    py: Python<'_>,
983    event_loop: &Bound<'_, PyAny>,
984    fut: &Bound<'_, PyAny>,
985    result: PyResult<Py<PyAny>>,
986) -> PyResult<()> {
987    let completer = cached_completer(py)?;
988    let (is_exc, value) = match result {
989        Ok(v) => (false, v),
990        Err(e) => (true, e.into_value(py).into_any()),
991    };
992    event_loop.call_method1("call_soon_threadsafe", (completer, fut, is_exc, value))?;
993    Ok(())
994}

1004/// Complete an `asyncio.Future` on its loop thread (HDL-7).
1005///
1006/// The future may already be settled when this runs: a cancelled future is left
1007/// alone, and an already-completed one is swallowed. Any other error propagates.
1008#[pyfunction]
1009pub(crate) fn complete_asyncio_future(
1010    fut: &Bound<'_, PyAny>,
1011    is_exc: bool,
1012    value: Py<PyAny>,
1013) -> PyResult<()> {
1014    if fut.call_method0("cancelled")?.is_truthy()? {
1015        return Ok(());
1016    }
1017    let py = fut.py();
1018    let (method, value) = if is_exc {
1019        // asyncio.Future.set_exception rejects a StopIteration (PEP 479) with a
1020        // TypeError; running as a call_soon_threadsafe callback it would be
1021        // logged and dropped, hanging the awaiter. Wrap any StopIteration
1022        // (including subclasses) in a RuntimeError -- how `raise StopIteration`
1023        // already surfaces out of a coroutine -- so the future can always settle.
1024        let value = if value.bind(py).is_instance_of::<PyStopIteration>() {
1025            PyRuntimeError::new_err("coroutine raised StopIteration")
1026                .into_value(py)
1027                .into_any()
1028        } else {
1029            value
1030        };
1031        ("set_exception", value)
1032    } else {
1033        ("set_result", value)
1034    };
1035    // HDL-7: publish only to a non-cancelled future (the guard above), and
1036    // swallow InvalidStateError from one already settled. Any other error is a
1037    // real failure and propagates.
1038    match fut.call_method1(method, (value,)) {
1039        Ok(_) => Ok(()),
1040        Err(e) => {
1041            if e.is_instance(py, &invalid_state_error(py)) {
1042                Ok(())
1043            } else {
1044                Err(e)
1045            }
1046        }
1047    }
1048}
