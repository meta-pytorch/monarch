Module child_process 

Source
Expand description

Spawns child processes from a thread that lives as long as the process.

On Linux, prctl(PR_SET_PDEATHSIG) fires when the thread that forked a child exits, not when the child’s parent process exits. A child forked from a tokio worker therefore dies with that worker, and tokio can retire a worker at any time, for example after block_in_place. Children that arm the death signal must be forked here instead, by one thread that never exits, so the signal fires only when the parent process does.

§Invariants

  • CPS-1 (spawner-outlives-children): every child returned by spawn_child is forked by the child-spawner thread, which does not exit while the process runs. Its request sender is never dropped, and a panic while spawning a command or dropping it is contained inside the thread’s loop.
  • CPS-2 (caller-runtime): the returned [Child] is registered with the runtime that called spawn_child: the caller’s handle is taken before the request is sent and entered on the spawner thread for the spawn.
  • CPS-3 (no-silent-fallback): spawn_child never forks on the calling thread; it has no path that calls [Command::spawn] there.
  • CPS-4 (caller-owns-child): the child returned by a successful spawn_child belongs to its caller from the moment the call returns: the handoff is synchronous, so there is no cancellation point between the fork and the return. A spawn that panics after forking, as tokio does for a runtime without I/O, returns an error and leaves that child unregistered.
