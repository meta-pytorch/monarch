9//! The seam between the generic connection transport and a concrete network
10//! protocol (quic today; tcp later).
11//!
12//! Everything about *establishment* — announcing identity, the hello, liveness
13//! reporting, gateway side channels, matching serves to joins, retry/backoff,
14//! graceful shutdown — lives in [`crate::net_transport`] and is identical across
15//! protocols. A [`Net`] implementation supplies only the raw networking: parsing an
16//! address, building the shared dialing state, binding a listener, dialing, and
17//! producing a [`NetConn`] that hands out ordered byte-stream pairs.
18//!
19//! ## Streams, addressed by index
20//!
21//! A connection hands out independent, ordered stream pairs on demand via
22//! [`NetConn::stream`], each addressed by an explicit `index`. The two peers name the
23//! same index for the two halves of one logical stream, so stream *k* on one side pairs
24//! with stream *k* on the other regardless of the order either side requests them — the
25//! index is carried on the wire (a small prefix), so the pairing can never drift.
26//! `priority` is the send priority (quic uses it to pack a higher-priority stream — the
27//! heartbeat stream — ahead of a backlogged data stream; tcp has no per-stream priority
28//! and ignores it).
29//!
30//! **Direction is a property of the connection, not the call.** A [`Net::connect`]
31//! yields a *dialer* connection whose [`NetConn::stream`] **opens** each stream (quic:
32//! `open_bi`; tcp: dials a fresh socket); a [`Net::accept`] yields an *acceptor*
33//! connection whose [`NetConn::stream`] **awaits** the peer's matching stream (quic:
34//! `accept_bi`, demultiplexed by the index prefix; tcp: the socket the listener routed
35//! to this connection for that index). Both peers just call `stream(k, prio)` — the
36//! generic transport never has to reason about who speaks first. This is what lets a
37//! plain tcp socket work: only the dialer can open one, so only the dialer's `stream`
38//! opens; the acceptor's waits.
39//!
40//! The connection knows nothing about heartbeats or parent/child roles. The generic
41//! transport picks the indices: index 0 is the data/control stream, index 1 is the
42//! heartbeat stream (a higher `priority`), and it may later request further data-stream
43//! indices for striping large messages.
44//!
45//! ## Laziness
46//!
47//! [`NetConn::stream`] returns an awaitable that touches the wire only on its first poll
48//! (quic dialer: `open_bi`; quic acceptor: an `accept_bi` demux; tcp dialer: a socket
49//! dial). The generic transport awaits the data stream immediately but can hold a
50//! heartbeat or data stream un-awaited until it is actually needed, so a message-only
51//! side channel (whose dialer never opens index 1) never establishes a heartbeat
52//! stream.

54use std::fmt::Debug;
55use std::future::Future;
56use std::net::SocketAddr;
57
58use tokio::io::AsyncRead;
59use tokio::io::AsyncWrite;
60use tokio::runtime::Handle;

62/// The network-protocol-specific operations the generic transport is built on.
63pub(crate) trait Net: Sized + 'static {
64    /// A cheap, cloneable dialing handle a connector or side-channel task owns and
65    /// dials through repeatedly (quic: a client `Endpoint` from the pool).
66    type Dialer: Clone + 'static;
67    /// A bound server an acceptor task owns and accepts connections on (quic: a
68    /// server `Endpoint`).
69    type Listener: 'static;
70    /// One established connection; hands out ordered stream pairs.
71    type Conn: NetConn + 'static;
72
73    /// Build the shared per-context networking state, lazily, on the first serve or
74    /// join (quic: install the crypto provider; TLS is loaded on first bind/dial).
75    ///
76    /// `runtime`, when `Some`, is the multi-threaded runtime the caller wants this
77    /// protocol's network *work* to run on (so it spreads across cores rather than
78    /// serializing on the command-loop thread). A protocol whose work lives in a
79    /// background driver (quic: the per-endpoint driver quinn spawns at endpoint
80    /// construction) builds its endpoints/sockets with this runtime entered, placing
81    /// that driver — and thus its crypto — on the pool. A protocol whose work lives in
82    /// the foreground stream poll (tcp/kTLS: the read/write syscalls happen when the
83    /// stream is polled) cannot relocate its work from here — the generic transport
84    /// spawns its data coroutines on the same runtime instead — so it ignores this.
85    /// `None` ⇒ everything stays on the command-loop thread (single-core default).
86    fn create(runtime: Option<Handle>) -> anyhow::Result<Self>;
87
88    /// Parse a transport url (e.g. `quic://[::1]:7001`, or a bare `@endpoint` tag)
89    /// into a socket address.
90    fn parse_addr(url: &str) -> anyhow::Result<SocketAddr>;
91
92    /// A dialing handle for `addr`'s address family, from the (lazily built) client
93    /// pool.
94    fn dialer(&mut self, addr: SocketAddr) -> anyhow::Result<Self::Dialer>;
95
96    /// Bind a server listener on `addr`. Streams are opened lazily and addressed by
97    /// index (see [`NetConn::stream`]), so the listener needs no stream count up front.
98    fn bind(&mut self, addr: SocketAddr) -> anyhow::Result<Self::Listener>;
99
100    /// The next inbound connection, or `None` once `listener` is closed. The returned
101    /// connection is an *acceptor* connection: its [`NetConn::stream`] awaits the peer's
102    /// streams rather than opening them.
103    async fn accept(listener: &Self::Listener) -> Option<Self::Conn>;
104
105    /// Dial `addr` once, or `None` on failure — the caller retries with backoff (a join
106    /// may precede its serve). The returned connection is a *dialer* connection: its
107    /// [`NetConn::stream`] opens streams. No stream is opened here (quic does complete
108    /// its handshake; tcp opens nothing until the first [`NetConn::stream`]), so a tcp
109    /// join's reachability is proven by the first `stream` call, not by `connect`.
110    async fn connect(dialer: &Self::Dialer, addr: SocketAddr) -> Option<Self::Conn>;
111
112    /// The default cap on simultaneous client connect *attempts* when
113    /// `MM_QUIC_MAX_CONCURRENT_CONNECTS` is unset (see [`crate::net_transport`]'s
114    /// connect throttle). `None` ⇒ unlimited; each protocol overrides with a concrete
115    /// bound. tcp needs a much smaller cap than quic: it opens `streams` OS sockets
116    /// *and* a TLS handshake per connection and pairs them on the acceptor, so a large
117    /// concurrent connect storm on the single-threaded runtime starves stragglers
118    /// (connections that never finish pairing), whereas quic multiplexes its streams on
119    /// one endpoint-paced connection.
120    fn default_connect_concurrency() -> Option<usize> {
121        None
122    }
123}
124
125/// An established connection. It knows nothing about heartbeats, roles, or
126/// preambles — it just hands out ordered streams, told per stream which side speaks
127/// first. `Debug` supplies the peer identity for diagnostics (quic: the remote
128/// address), used by the heartbeat send log.
129///
130/// `Clone` is cheap and shares one underlying connection: the reader, the writer, and
131/// the heartbeat task each hold a clone and open the streams they own via
132/// [`Self::stream`] (for striping the reader and writer open their own data streams the
133/// same way), with no half handed between tasks. A quic dialer clones its `Connection`;
134/// the quic/tcp acceptors clone a request-sender to their demux; a tcp dialer clones
135/// its dial handle.
136///
137/// `Send` so a data coroutine holding the handle — the writer, the reader, and their
138/// striping objects that open their own data streams inline — can run on the data
139/// runtime.
140pub(crate) trait NetConn: Debug + Clone + Send + 'static {
141    /// The send half of a stream; framing drives it via [`AsyncWrite`]. It keeps the
142    /// underlying connection alive for its lifetime. `Send` so the data writer
143    /// coroutine can run on a multi-threaded runtime (the connection handle and the
144    /// heartbeat stream stay single-threaded; only the two data halves cross threads).
145    type Send: AsyncWrite + Unpin + Send + 'static;
146    /// The receive half of a stream; framing drives it via [`AsyncRead`]. It keeps
147    /// the underlying connection alive for its lifetime. `Send` for the same reason as
148    /// [`Self::Send`] — the data reader coroutine may run off the command-loop thread.
149    type Recv: AsyncRead + Unpin + Send + 'static;
150    /// The awaitable that materializes one stream's halves on first poll. `Send` so a
151    /// data coroutine on the data runtime can open a striping data stream inline (the
152    /// acceptor's variant just messages its demux; the dialer's opens/dials directly).
153    type Stream: Future<Output = std::io::Result<(Self::Send, Self::Recv)>> + Send + 'static;
154
155    /// An awaitable for the stream addressed by `index`, paired with the peer's stream
156    /// of the same index. On a *dialer* connection it opens the stream; on an *acceptor*
157    /// connection it awaits the peer's matching one (see the module docs). The index is
158    /// carried on the wire so the two peers' *k*-th streams pair up regardless of request
159    /// order. `priority` is the send priority (quic; tcp ignores it) — the transport
160    /// gives the heartbeat stream a higher priority than the data stream so a beat is
161    /// packed ahead of backlogged data. Nothing touches the wire until the returned
162    /// future is polled.
163    fn stream(&self, index: usize, priority: i32) -> Self::Stream;
164}
