Module token

Expand description

Connect to an existing Python actor mesh using a token string.

An actor publishes a token for a Python actor mesh. Another process uses it to obtain a reference and call the mesh’s endpoints. Connecting does not add actors to the mesh.

The actor whose instance publishes the token owns its rendezvous actor and receives each connecting actor’s address. It need not be an actor in the published mesh. Once the publishing actor stops, the token no longer accepts connections.

connect() returns a pending mesh with the region advertised in the token. Its calls wait for the rendezvous to supply the actual mesh reference.

§Token invariants (PYTK-*)

  • PYTK-1 (parse before sending). An invalid timeout or mesh token, including an invalid region, raises ValueError before opening a reply port or sending a join. Parsing preserves a valid region’s offset and strides.
  • PYTK-2 (reference only through join). The token supplies the region, not the mesh reference. connect() returns without waiting; queued calls wait for a joined reference whose region matches the token’s region.
  • PYTK-3 (connection failures stay local). A failed join is shared by initialization and reply-bearing endpoint calls. A reply timeout closes the reply port, not the caller’s actor, and does not retract the request. Fire-and-forget calls return no failure outcome.
  • PYTK-4 (publisher owns rendezvous). Publication neither changes mesh ownership nor permits the rendezvous to outlive its publishing actor.
