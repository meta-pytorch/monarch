9//! Connect a new client to a trainer that is already running.
10//!
11//! This program has two roles, run in separate processes:
12//!
13//! - `trainer` runs a simulated training loop as an ordinary Tokio task, not
14//!   an actor. Monarch does not start or supervise that loop. Each step updates
15//!   a step count and loss using the current learning rate.
16//! - `client` connects later, reads the trainer's state, changes its learning
17//!   rate, reads the state again, and exits. The trainer keeps running.
18//!
19//! The trainer embeds a Monarch proc containing three actors:
20//!
21//! - [`ProbeHost`] is the root actor. It creates the other two actors, writes
22//!   the token file, and handles their supervision events.
23//! - [`Probe`] is a child of `ProbeHost`. It shares the loop's live
24//!   [`TrainerState`] behind a mutex and answers clients' state queries and
25//!   learning-rate changes. It is called a probe because clients can use it
26//!   to peer into the running trainer.
27//! - The rendezvous actor is another child of `ProbeHost`, created by
28//!   `token::create()`. It handles join requests and gives clients a reference
29//!   to `Probe`; it does not answer the training-state requests itself.
30//!
31//! The training loop is not a fourth actor. It remains an ordinary Tokio task,
32//! separate from this supervision tree. Clients do not own the loop or become
33//! its controller.
34//!
35//! The client also embeds a Monarch proc. `proc.client("client")` creates a
36//! lightweight actor instance with its own actor address and mailbox, but no
37//! actor message loop like `Probe` has. Ordinary Rust code sends requests and
38//! awaits replies through ports belonging to this client instance.
39//!
40//! To let a client find the probe, the trainer writes a token to a file.
41//! The token string contains a reference to the rendezvous actor. The client
42//! reads and parses the token, then uses that reference to send a join request
43//! to the rendezvous actor. The request carries the client's actor address and
44//! a reply port; the client does not send the token itself.
45//!
46//! The rendezvous actor handles the request by sending the client's actor
47//! address to `ProbeHost` as a join notification, then sending a typed reference
48//! to `Probe` to the client's reply port. `ProbeHost` logs the notification.
49//! The client then sends [`Snapshot`] and [`SetLearningRate`] requests directly
50//! to `Probe`, not through the rendezvous actor.
51//!
52//! This example chooses to give the trainer the client's actor address so
53//! `ProbeHost` can log who connected. The token mechanism does not require an
54//! actor address: other tokens can exchange other serializable values. Giving
55//! the trainer this address does not make the trainer send requests to the
56//! client or start supervising it.
57//!
58//! `ProbeHost` handles child supervision events rather than letting them fail the
59//! root actor and terminate the trainer process. Joining establishes contact,
60//! not remote supervision: clients can come and go independently. Multiple
61//! clients can use the token, but it stops working when its creator stops.
62//!
63//! The roles can run on the same machine or on separate hosts. This example
64//! uses plaintext TCP, which is fine on one machine or within one datacenter;
65//! between hosts in different regions or datacenters, use an encrypted
66//! transport such as `ChannelTransport::MetaTls(TlsMode::Hostname)` instead.
67//! Each proc listens on a non-loopback TCP address resolved from its machine's
68//! hostname. Each hostname must resolve to such an address, and the two hosts
69//! must be able to reach each other's listeners: requests travel to the
70//! trainer, and replies travel back to the client. Copy the trainer's token
71//! file to the client host, or place it on a shared filesystem, before
72//! starting the client.
73//!
74//! It demonstrates late attachment, not authentication or a Python API.

103/// Read `Token<Gives, Gets>` from the trainer's point of view:
104/// the trainer gives each joining client an `ActorRef<ProbeLike>` and gets
105/// that client's `ActorAddr`. The rendezvous actor delivers both values.
106///
107/// The `Probe` actor accepts `Snapshot` and `SetLearningRate` messages.
108/// The trainer only logs the client's address.
109type ProbeToken = Token<ActorRef<ProbeLike>, ActorAddr>;
110
111/// Delay between simulated training steps.
112const STEP_INTERVAL: Duration = Duration::from_millis(200);
113/// Maximum time the client waits for a join response or a probe reply.
114const REPLY_TIMEOUT: Duration = Duration::from_secs(10);

116/// State of the simulated training loop, shared with the probe.
117#[derive(Debug)]
118struct TrainerState {
119    /// Number of simulated training steps completed.
120    step: u64,
121    /// Simulated loss, multiplied by `1.0 - learning_rate` at each step.
122    loss: f64,
123    /// Rate used by the training loop; clients can change it through `Probe`.
124    learning_rate: f64,
125}
126
127/// The trainer's state as reported to a client.
128#[derive(Clone, Debug, Serialize, Deserialize, Named)]
129struct TrainerStatus {
130    /// Number of completed training steps when this snapshot was taken.
131    step: u64,
132    /// Simulated loss when this snapshot was taken.
133    loss: f64,
134    /// Learning rate in use when this snapshot was taken.
135    learning_rate: f64,
136}
137// Register its type name, hash and JSON formatter for message diagnostics.
138// The Serde derives above handle serialization; registration is for inspection.
139wirevalue::register_type!(TrainerStatus);

141/// Report the trainer's current state.
142#[derive(Clone, Debug, Serialize, Deserialize, Named)]
143struct Snapshot {
144    /// Client's reply port, where the probe sends one `TrainerStatus`.
145    reply: OncePortRef<TrainerStatus>,
146}
147wirevalue::register_type!(Snapshot);

149/// Change the learning rate; the reply carries the previous one.
150#[derive(Clone, Debug, Serialize, Deserialize, Named)]
151struct SetLearningRate {
152    /// New learning rate for the trainer to use on subsequent steps.
153    learning_rate: f64,
154    /// Client's reply port, where the probe sends the previous learning rate.
155    reply: OncePortRef<f64>,
156}
157wirevalue::register_type!(SetLearningRate);

159// Define the probe's client-facing interface as a named set of messages.
160// The macro generates `ProbeLike`, a marker type, not another actor or message.
161//
162// `ActorRef<ProbeLike>` is a reference to an actor that accepts `Snapshot` and
163// `SetLearningRate`. Clients can send those messages without knowing the
164// actor's concrete type, its fields or how its handlers work. This is the
165// reference the trainer gives clients through `ProbeToken`.
166//
167// When `probe.bind::<ProbeLike>()` creates that reference, the generated code
168// requires the actor to implement `Handler<Snapshot>` and
169// `Handler<SetLearningRate>`, and binds a message port for each of them.
170// The `Probe` handlers below do the work; this macro neither implements them
171// nor spawns an actor.
172hyperactor::behavior!(ProbeLike, Snapshot, SetLearningRate);

174/// The actor clients contact to inspect and adjust the running trainer.
175///
176/// `Snapshot` returns a copy of the shared training state. `SetLearningRate`
177/// changes the rate used by later steps and replies with the previous rate.
178/// The loop runs as a separate Tokio task; this actor does not drive or
179/// supervise it.
180#[derive(Debug)]
181#[hyperactor::export(Snapshot, SetLearningRate)]
182struct Probe {
183    /// Live state shared with the training loop, not a copy.
184    /// `Arc` lets the loop and this actor own it together; `Mutex` keeps
185    /// their reads and updates from overlapping.
186    state: Arc<Mutex<TrainerState>>,
187}
188
189/// Use Hyperactor's default actor lifecycle; no custom startup or shutdown.
190/// The `Handler` implementations below define how client requests are answered.
191impl Actor for Probe {}
192
193#[async_trait]
194impl Handler<Snapshot> for Probe {
195    /// Reply with the trainer's state at the moment this request is handled.
196    /// Copy all three fields under one lock so they describe the same instant,
197    /// then release the lock before sending the reply to the client.
198    async fn handle(&mut self, cx: &Context<Self>, message: Snapshot) -> anyhow::Result<()> {
199        let status = {
200            let state = self.state.lock().unwrap();
201            TrainerStatus {
202                step: state.step,
203                loss: state.loss,
204                learning_rate: state.learning_rate,
205            }
206        };
207        message.reply.post(cx, status);
208        Ok(())
209    }
210}
211
212#[async_trait]
213impl Handler<SetLearningRate> for Probe {
214    /// Replace the live learning rate under the same lock used by the loop.
215    /// Subsequent training steps use the new rate. Release the lock, log the
216    /// change, and reply with the previous rate so the client knows what changed.
217    async fn handle(&mut self, cx: &Context<Self>, message: SetLearningRate) -> anyhow::Result<()> {
218        let previous = std::mem::replace(
219            &mut self.state.lock().unwrap().learning_rate,
220            message.learning_rate,
221        );
222        println!(
223            "trainer: learning rate changed from {previous} to {}",
224            message.learning_rate
225        );
226        message.reply.post(cx, previous);
227        Ok(())
228    }
229}

231/// Root actor in the trainer process that creates the probe and join token.
232///
233/// The `Probe` and token's rendezvous actor are its supervised children.
234/// It publishes the token and logs their supervision events without letting
235/// those events fail this root actor and terminate the trainer process.
236/// The training loop is a separate Tokio task, not a child actor.
237#[derive(Debug)]
238struct ProbeHost {
239    /// The loop's live state, passed to the `Probe` actor when it is spawned.
240    state: Arc<Mutex<TrainerState>>,
241    /// File where the trainer writes the token string for later clients to read.
242    token_file: PathBuf,
243}
244
245#[async_trait]
246impl Actor for ProbeHost {
247    /// Spawn the probe and publish its join token for later clients.
248    /// `token::create()` spawns the rendezvous actor and returns its token.
249    /// Both actors become children of this `ProbeHost`; the training loop
250    /// remains a separate task sharing the same state.
251    async fn init(&mut self, this: &Instance<Self>) -> anyhow::Result<()> {
252        // Spawn a supervised child that accesses the loop's existing state.
253        // Cloning the `Arc` shares ownership; it does not copy the state.
254        let probe = this.spawn(Probe {
255            state: self.state.clone(),
256        });
257        // This call spawns the rendezvous actor; it does not just format a token.
258        // The returned token contains a reference to that new actor.
259        let token: ProbeToken = token::create(
260            // Parent the rendezvous actor under this `ProbeHost`, not `Probe`.
261            this,
262            // Give each client the probe's two-message interface.
263            probe.bind::<ProbeLike>(),
264            // Route join notifications to this actor's
265            // `Handler<token::Joined<ActorAddr>>` implementation.
266            this.port::<token::Joined<ActorAddr>>().bind(),
267            // `Multi`: accept clients while the rendezvous actor is alive.
268            TokenOptions::default(),
269        )?;
270        // Share the token through a file, outside Monarch's messaging system.
271        // A later client reads it to learn how to reach the rendezvous actor.
272        write_text(&self.token_file, &token.to_string()).await?;
273        println!("trainer: token written to {}", self.token_file.display());
274        Ok(())
275    }
276
277    /// Log a supervision event from `Probe` or the token's rendezvous actor.
278    ///
279    /// `Ok(true)` tells Hyperactor the event is handled: do not fail this
280    /// root actor and terminate the trainer process because of it.
281    /// Handling the event does not restart a failed child.
282    async fn handle_supervision_event(
283        &mut self,
284        _this: &Instance<Self>,
285        event: &ActorSupervisionEvent,
286    ) -> anyhow::Result<bool> {
287        println!("trainer: probe event: {event}");
288        Ok(true)
289    }
290}

292#[async_trait]
293impl Handler<token::Joined<ActorAddr>> for ProbeHost {
294    /// Log the address supplied by a client joining through the token.
295    /// The rendezvous actor sends this notification with the client's
296    /// `ActorAddr`, not the probe reference it gives to the client.
297    /// This handler only logs the join; it does not start remote supervision.
298    async fn handle(
299        &mut self,
300        _cx: &Context<Self>,
301        message: token::Joined<ActorAddr>,
302    ) -> anyhow::Result<()> {
303        println!("trainer: client {} connected", message.peer);
304        Ok(())
305    }
306}

308#[tokio::main]
309async fn main() -> anyhow::Result<()> {
310    // Each invocation runs one role. `?` returns argument errors before
311    // starting either role; awaiting the selected role keeps main alive.
312    match parse_args()? {
313        // Run the training loop and actor tree until `ProbeHost` stops.
314        Role::Trainer { token_file } => run_trainer(token_file).await,
315        // Join the trainer found through the token, read and change its state,
316        // then exit. `learning_rate` is the client's requested new rate.
317        Role::Client {
318            token_file,
319            learning_rate,
320        } => run_client(token_file, learning_rate).await,
321    }
322}

324/// Start the simulated training loop and the actors clients use to reach it.
325/// The loop and `Probe` share live state, but run independently: the loop is
326/// a Tokio task, while `ProbeHost` creates and supervises the probe and
327/// rendezvous actors. Wait for `ProbeHost` to stop before returning.
328async fn run_trainer(token_file: PathBuf) -> anyhow::Result<()> {
329    // Allocate one shared state for the loop and the probe. The mutex keeps
330    // training steps and client reads or learning-rate changes from overlapping.
331    let state = Arc::new(Mutex::new(TrainerState {
332        step: 0,
333        loss: 1.0,
334        learning_rate: 0.01,
335    }));
336
337    // Give the task another reference to the same state, not a copy of it.
338    // Tokio schedules this loop independently of the Monarch actors.
339    let loop_state = state.clone();
340    tokio::spawn(async move {
341        loop {
342            // Sleep without holding the mutex, so the probe can serve clients
343            // between steps. Each step uses the latest learning rate.
344            tokio::time::sleep(STEP_INTERVAL).await;
345            let mut state = loop_state.lock().unwrap();
346            state.step += 1;
347            state.loss *= 1.0 - state.learning_rate;
348            // Report progress every 25 steps rather than on every update.
349            if state.step.is_multiple_of(25) {
350                println!(
351                    "trainer: step {} loss {:.4} learning rate {}",
352                    state.step, state.loss, state.learning_rate
353                );
354            }
355        }
356    });
357
358    // Embed a Monarch actor runtime in this trainer process. It will host
359    // `ProbeHost`, `Probe`, and the token's rendezvous actor; creating a `Proc`
360    // does not launch another OS process. Its TCP listener uses a non-loopback
361    // address so clients on this machine or other hosts can reach these actors.
362    let proc = Proc::direct(
363        ChannelAddr::any(ChannelTransport::Tcp(TcpMode::Hostname)),
364        "late_join_trainer".to_string(),
365    )?;
366    // Start `ProbeHost`. Its init() spawns `Probe` with the shared state, then
367    // calls `token::create()` to spawn the rendezvous actor, and writes the
368    // token file.
369    let host = proc.spawn(ProbeHost { state, token_file });
370    // Wait for the root actor to stop, not for the training loop to finish.
371    // This keeps the trainer role alive while clients join and use the probe.
372    host.await;
373    Ok(())
374}

376/// Join the running trainer, read its state, change its learning rate, and
377/// read its state again. The token locates the rendezvous actor; joining
378/// returns a `Probe` reference for the subsequent requests. Each reply wait
379/// is bounded by `REPLY_TIMEOUT`. Returning does not stop the trainer.
380async fn run_client(token_file: PathBuf, learning_rate: f64) -> anyhow::Result<()> {
381    // Read the token published by the trainer, possibly copied to this host.
382    // Parsing recovers the rendezvous reference and checks the exchanged types.
383    let token: ProbeToken = tokio::fs::read_to_string(&token_file)
384        .await?
385        .trim()
386        .parse()?;
387    // The client also needs a non-loopback listener: the trainer sends replies
388    // to this proc's ports, which must be reachable from the trainer's host.
389    let proc = Proc::direct(
390        ChannelAddr::any(ChannelTransport::Tcp(TcpMode::Hostname)),
391        "late_join_client".to_string(),
392    )?;
393    // Create our actor identity and mailbox without an actor message loop.
394    // This function sends requests and reads replies through the client's ports.
395    let client = proc.client("client");
396
397    // Open a reply port for the rendezvous actor's acceptance or rejection.
398    let (result_port, mut result_rx) = client.open_port::<token::JoinResult<ActorRef<ProbeLike>>>();
399    // Use the token's reference to send a join request to the rendezvous actor.
400    // Give our actor address for `ProbeHost` to log, and our reply port for the
401    // rendezvous actor's answer. The token itself is not sent.
402    token.join(&client, client.self_addr().clone(), result_port.bind())?;
403    // Wait for an answer without waiting indefinitely. Acceptance supplies the
404    // `Probe` reference; rejection returns an error instead of querying the probe.
405    let probe = match tokio::time::timeout(REPLY_TIMEOUT, result_rx.recv()).await {
406        Err(_) => anyhow::bail!("no answer from the trainer; is it running?"),
407        Ok(result) => match result? {
408            token::JoinResult::Joined { peer } => peer,
409            token::JoinResult::Rejected { reason } => {
410                anyhow::bail!("the trainer rejected the connection: {reason}")
411            }
412        },
413    };
414    println!("client: connected; probe is {}", probe.actor_addr());
415
416    // Contact `Probe` directly for the initial state; rendezvous is no longer
417    // involved. `snapshot()` sends a request with its own one-shot reply port.
418    let status = snapshot(&client, &probe).await?;
419    println!(
420        "client: step {} loss {:.4} learning rate {}",
421        status.step, status.loss, status.learning_rate
422    );
423
424    // Ask `Probe` to replace the shared learning rate. Give it a one-shot port
425    // for returning the previous rate, not another trainer-state snapshot.
426    let (reply, reply_rx) = client.open_once_port::<f64>();
427    probe.post(
428        &client,
429        SetLearningRate {
430            learning_rate,
431            reply: reply.bind(),
432        },
433    );
434    // The first `?` propagates a timeout; the second propagates a receive error.
435    // A reply means the handler has replaced the rate used by training steps.
436    let previous = tokio::time::timeout(REPLY_TIMEOUT, reply_rx.recv()).await??;
437    println!("client: learning rate changed from {previous} to {learning_rate}");
438
439    // Read again after the change. Training continued during these requests,
440    // so the step count and loss may also differ from the initial snapshot.
441    let status = snapshot(&client, &probe).await?;
442    println!(
443        "client: step {} loss {:.4} learning rate {}",
444        status.step, status.loss, status.learning_rate
445    );
446    Ok(())
447}

449/// Ask `Probe` for the trainer's current state and await its one-shot reply.
450/// The reply port belongs to `client`; the state is copied when `Probe`
451/// handles the request. Return an error on timeout or receive failure.
452async fn snapshot(
453    client: &hyperactor::Client,
454    probe: &ActorRef<ProbeLike>,
455) -> anyhow::Result<TrainerStatus> {
456    let (reply, reply_rx) = client.open_once_port::<TrainerStatus>();
457    probe.post(
458        client,
459        Snapshot {
460            reply: reply.bind(),
461        },
462    );
463    Ok(tokio::time::timeout(REPLY_TIMEOUT, reply_rx.recv()).await??)
464}

466/// Write `text` followed by a newline, creating the file or replacing its
467/// contents. Used to publish the token; return an error if writing fails.
468async fn write_text(path: &Path, text: &str) -> anyhow::Result<()> {
469    tokio::fs::write(path, format!("{text}\n")).await?;
470    Ok(())
471}

473/// Which role this invocation runs, with its command-line settings.
474#[derive(Debug)]
475enum Role {
476    /// Run the training loop and host the probe and rendezvous actors.
477    Trainer {
478        /// File where the trainer writes the token for later clients to read.
479        token_file: PathBuf,
480    },
481    /// Join an existing trainer, inspect its state, and change its learning rate.
482    Client {
483        /// File containing the trainer's token, shared or copied to this host.
484        token_file: PathBuf,
485        /// New learning rate the client asks the probe to set.
486        learning_rate: f64,
487    },
488}
489
490fn parse_args() -> anyhow::Result<Role> {
491    const USAGE: &str = "usage: late_join trainer --token-file PATH | late_join client --token-file PATH [--learning-rate RATE]";
492    let mut args = std::env::args().skip(1).collect::<Vec<_>>();
493    if args.is_empty() {
494        anyhow::bail!(USAGE);
495    }
496    let role = args.remove(0);
497    let token_file = PathBuf::from(
498        take_flag(&mut args, "--token-file")?
499            .ok_or_else(|| anyhow::anyhow!("missing --token-file; {USAGE}"))?,
500    );
501    let role = match role.as_str() {
502        "trainer" => Role::Trainer { token_file },
503        "client" => Role::Client {
504            token_file,
505            learning_rate: take_flag(&mut args, "--learning-rate")?
506                .map(|rate| rate.parse())
507                .transpose()?
508                .unwrap_or(0.05),
509        },
510        _ => anyhow::bail!("unknown role {role}; {USAGE}"),
511    };
512    if !args.is_empty() {
513        anyhow::bail!("unknown arguments: {}", args.join(" "));
514    }
515    Ok(role)
516}

518/// Remove `flag` and its value from `args`, returning the value.
519fn take_flag(args: &mut Vec<String>, flag: &str) -> anyhow::Result<Option<String>> {
520    let Some(index) = args.iter().position(|arg| arg == flag) else {
521        return Ok(None);
522    };
523    args.remove(index);
524    if index >= args.len() {
525        anyhow::bail!("missing value for {flag}");
526    }
527    Ok(Some(args.remove(index)))
528}
